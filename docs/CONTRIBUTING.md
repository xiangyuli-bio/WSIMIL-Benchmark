# 新方法接入与验收

1. 在 methods.json 对应条目固定论文身份、代码来源、commit 和许可。相同缩写按不同论文保持不同 ID。
2. 确定输入与任务：冻结特征、真实坐标、多尺度、图、RGB、文本、组学、支持集或持续任务序列。不能虚构缺失输入。
3. 在 models/extended 等模块实现模型；在 recipes/engine 实现完整的训练过程。新的适配器可拆成独立模块，不必继续扩大单一文件。
4. 使用 build_catalog.py 为经过实现的配置登记独立 profile。目录条目和 profile 的数量分别统计。
5. 验证实例梯度、辅助损失、关键参数更新、保存恢复、推理身份及依赖失败行为。教师/原型/图预计算必须保存进 checkpoint 或带哈希的阶段产物。
6. 添加明确的数据参考实验，保存实际日志、预测、成本、作者设定与本配置的差异。合成测试只改变 software 状态。
7. 最后才能将相应配置纳入正式兼容矩阵。不能依据测试分数筛掉低表现方法。

库内主循环目前适配互斥分类、有序评价和 Cox 生存。组学/文本/持续学习等需要新增经过验证的数据与 trainer 接口，不应让一个 `forward` 成功就把目录条目标成完整支持。

对于额外依赖，优先单独环境并固定版本。参数不识别、缺权重或核心库缺失应报错。不能捕获导入错误后自动替换原算法。

来源获取工具拒绝覆盖脏工作区或不同版本的目录。发布第三方代码前检查对应来源的许可并保留声明。加入 CI 的测试应验证行为与必要机制，不以方法数量作为验收标准。
